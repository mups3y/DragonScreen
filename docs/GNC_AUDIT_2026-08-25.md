# GN&C fidelity audit — 2026-08-25

A line-by-line audit of the RSS DragonScreen flight software against real SpaceX/NASA GN&C practice,
with online research grounding each judgement. Goal (user): a true adaptive autopilot making live
calculations and the same choices SpaceX/NASA would, with correct control at all times.

## Real-GN&C references used (primary/authoritative)

- **Ascent (upper stage):** Unified Powered Flight Guidance (Brand, Brown & Higgins, Draper Lab, NASA
  1973) — linear-tangent predictor-corrector, Shuttle/SLS heritage. Cross-checked against the PEGAS
  reference implementation (Noiredd/PEGAS-MATLAB `unifiedPoweredFlightGuidance.m`).
- **Booster landing:** Blackmore, *Autonomous Precision Landing of Space Rockets* (NAE) — convex
  optimization / G-FOLD, CVXGEN, fuel-optimal max-min-max, <100 ms solves, 99% dispersions in the LZ.
- **Rendezvous:** NASA/SpaceX approach-ellipsoid + 200 m keep-out-sphere; **passively-safe guidance**
  is a real design principle (SpaceX patent "Fail-safe vehicle rendezvous in case of total control
  failure"; passively-safe convex rendezvous literature) — validates the passive-abort work.
- **Entry:** Apollo/Orion bank-angle lifting entry (roll the lift vector; vertical lift = L·cos(bank)).

## Bugs found and FIXED this session

### #1 — UPFG `vthrust` missing its lateral turning term  (`pure/Upfg.cs`)
`rthrust` correctly carried `−(S·φ + Q·φ̇)·î_λ̇` but `vthrust` dropped the matching
`−(L·φ + J·φ̇)·î_λ̇`. Canonical Brand-Brown-Higgins UPFG has it on both. The omission fed the dropped
lateral velocity back into `vbias` as a spurious bias, so the Vgo correction converged to a slightly
wrong steering each call. **Fixed**; UPFG convergence test still green.

### #2 — RSS deorbit-orbit uses stock-Kerbin target → phase-down refuse-loop  (`DeorbitOps.cs`)
`DeorbitOrbit.TargetApoapsisM/PeriapsisM` = 85.1×79.2 km — a **stock-Kerbin** landing orbit. On RSS
Earth (140 km atmosphere) 79 km is sub-atmospheric, so every phase-down burn toward it is refused by
`NodeExecutor.PeriapsisSafe` (140 km floor) — a futile refuse-loop, and the crew ends up de-orbiting
from full station altitude with Kerbin-fitted constants. **Fixed:** only phase down when the landing
orbit is a valid orbit for *this* body (`TargetPeriapsisM > atmosphereDepth`). Stock Kerbin (70 km
atmo) still phases down; RSS Earth skips to the closed-loop deorbit — which is what the real Crew
Dragon does (deorbit from near its orbit, not a low parking pass).

### #3 — First-stage g-limit fed the LIVE (throttled) thrust → ~4.2 g oscillation  (`pure/Ascent.cs` + `AutoPilot.cs`)
User-observed 4.2 g against a 3.5 g cap. `GThrottle` divided `AvailableThrust` (summed `finalThrust`,
i.e. the *already-throttled* thrust) by mass and treated it as the full-throttle acceleration. So the
instant it throttled to the cap, "full accel" read the cap, `GThrottle` returned 1.0, and the engine
went back to full — oscillating 3.5↔4.5 g, peaking ~4.2. **Fixed:** added `AscentInputs.MaxThrustKn`
(full-throttle `MaxThrustOutputVac` of the lit engines) and sized the cap on it. The cap is now stable:
`throttle = gLimit/(MaxThrust/mass)`, independent of the current throttle. 4 regression tests added.

### #4 — Second stage / UPFG held full throttle to SECO with no g-limit  (`AutoPilot.cs`)
The MVac (~980 kN) on a light stage + Dragon pulls 8–12 g near SECO at full throttle; real Crew Dragon
throttles the upper stage there. **Fixed:** the crew g-cap now applies to UPFG too (`Ascent.GThrottle`
on the S2's `MaxThrustKn`). UPFG is closed-loop on the live thrust, so it re-solves Tgo for the reduced
throttle and still closes the orbit. The 0.35 floor mirrors the MVac's real ~40% minimum, so the brief
~4 g at the very end matches the real vehicle's SECO g-load.

### (earlier this session)
- **Passive-abort on the rendezvous CW burns** (`pure/CwTargeting.cs` + `NamedRendezvousOps.cs`): each
  terminal transfer propagates its free-drift (arrival burn never made) and prefers the cheapest
  transfer that keeps a missed burn ≥250 m from the station for a full orbit. Instrumented `rv_passiveM`.
  This is the real SpaceX "fail-safe rendezvous / passively-safe" principle made a proven property.
- **Plane∩phase launch window** (`pure/PlaneWindow.cs` + `LaunchWindowOps.cs`): picks the plane-crossing
  *day* that also lands the ISS in a bounded catch-up band ahead, instead of the first crossing (which
  left us 118° behind). Real Dragon: launch *time* = plane, launch *date* = phase.

## RSS calibration findings (constants Kerbin-fitted — need an RSS return flight to measure, NOT blind-fixable)

- **`pure/Overflight.cs`** `DescentTimeS = 845 s` / `LagArcFrac = 0.358` are Kerbin-fitted. On RSS the
  ISS period is ~5570 s, so `LandLagS = 845 − 0.358·5570 = −1149 s` — a negative land-lag. The ISS is
  genuinely inclined (51.6°), so the cross-track pass selection matters and is mis-calibrated. Not a
  logic bug; needs the real Earth descent time (~30+ min) measured on the first return flight.
- **Booster aim (~4.9 km long):** the drag-aware Mach prediction is correctly wired
  (`ImpactPredictor.PredictBooster` → `BoosterDrag.DragFactor`), and the integrator is verified correct.
  The residual is **staging energy** (natural impact ~562 km vs the 542 km barge) coupled to ascent
  MECO — tune `EntryBurnReserveFrac`/`EntryAimBufferM`/the bc curve and, the deeper lever, a softer
  MECO. A data-tuning loop, not a code defect.
