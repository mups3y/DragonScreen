- **⛔ RENDEZVOUS — RAN OUT OF MMH before terminal approach (no dock). ROOT CAUSE (data-established, NOT yet fixed):** the far-field **TRANSFER** burn (`Phasing.FarGuide`: raise ap toward the station, prograde, bounded — *intent is correct*) is grossly **propellant-inefficient**.
  - The burn (MET 18,577→18,805) raised **ap 200→406 km** (pe held ~197) — a ~**61 m/s** orbital maneuver by vis-viva — but consumed **1171 kg = ~85% of MMH** (`mmh_frac` 0.90→0.09; ~370 m/s by rocket-eq at Isp≈300). **~15–25% efficient.** The tank then emptied during `ApproachInit`; no fuel for velocity-match/dock.
  - **Why so wasteful:** it uses continuous low-thrust **Draco translation** (the Dragon has no main engine), which (a) cancels ~33% internally (`rcsbal_force_frac` = 0.67), and (b) spends the rest over a long continuous arc rather than an impulsive Δv — and there is **no propellant-budget guard** (`dv_planned_mps` is blank for all 1133 Phasing rows; the transfer burns purely on the "ap < target" condition). Attitude was well-held (att_err 2.6°), so this is an **actuation-efficiency / burn-strategy** problem, not a pointing one.
  - **INVESTIGATION CONCLUSION (2026-08-31, code + config + flight):** the loss is **inherent RCS-translation inefficiency**, not the phasing logic and not attitude pointing.
    - **Draco Isp = 240 s** (`TE_CD2_POD.cfg`, `atmosphereCurve key 0 240`; 2× `ModuleRCSFX`, 1.5 kN, MonoProp). So the 61 m/s ap-raise should cost **~205 kg** but cost **1171 kg → 21% efficient (~5× waste)**. Not a low-Isp artefact — a real efficiency loss.
    - **Mechanism:** the burn is a continuous full **`trans_z`** on the Dragon's 16 Dracos, which are **2 all-axis `ModuleRCSFX` blocks with only a per-module `thrustPercentage` — no per-thruster control** (`docs/RCS_BALANCE_FINDING.md`). KSP's naive "fire every thruster with a component along the demand" delivers a small **net** prograde force per unit gross thrust (much of it cancels/goes off-axis), and induces a large self-torque (`rcsbal_torque_naive` ≈ 8.5 kN·m, ~60% of the capsule's ~14 attitude authority) that the loop counter-fires (`act_roll` active 78% of ticks) — but attitude firing is the minority; **translation cancellation dominates** (`trans_z`=1.0 continuous). Pointing is fine (att_err/AoA 2.6°).
    - **Why it strands the mission:** at 100% efficiency the 61 m/s raise is ~17% of the MMH tank (affordable, dock reachable); at 21% it is ~85% → nothing left for velocity-match/dock. **The far-field phasing strategy (insert LOW+fast, then raise ap) implicitly assumes more Δv than a Draco-only vehicle has at this efficiency.**

  - **✅ BUDGET SIZED (2026-08-31, measured + analytic; A1 validated).** Dragon full-MMH useful Δv = **66 m/s** (Isp 240, 21% eff, mass 9940→8707 kg). Required Δv by insertion margin below the station (transfer + null-relV-at-handoff + ~15 m/s braking, all @21%): margin **207 km (current) → 140 m/s ≫ 66 → strands** (the model reproduces the flight); **50 km → 49 m/s ✅** (4.0°/orbit phasing); 30 km → 37.6 ✅ (2.4°/orbit); 10 km → 37.6 ✅ but 0.8°/orbit (too slow). **Recommended margin ≈ 50 km** (fits with headroom, phases ~4°/orbit). Key assumption: 21% applies to terminal burns too (measured for the prograde transfer; confirm per-axis in re-fly — if lower, use a smaller margin, slower phasing).
  - **✅ DIRECTION CHOSEN (owner, 2026-08-31): (A) insert closer — the ascent delivers the Dragon near the station altitude (~416 km here; `parkAltM` = station − `CoEllipticBelowM` 10 km), so the far-field Hohmann injection (`AscentControl.cs:152` currently inserts CIRCULAR at `mission.ApoKm`=200 km) shrinks toward 0.** Design sub-options for the plan: **A1** insert circular a tunable margin *below* the station (small residual raise, affordable at 21%; phases slower — the trade to tune) vs **A2** insert elliptical (pe low for fast phasing, ap at station; needs ascent to target an ellipse + far-field phase-to-apoapsis). **Caveat to size in the plan:** the terminal CW approach/velocity-match/dock still run on 21%-efficient RCS, so the plan must budget those against the freed MMH. **✅ A1 IMPLEMENTED (2026-08-31, uncommitted→committing):** `AscentControl` now inserts `ParkBelowStationKm` (default 50) below the selected target's periapsis when a rendezvous target is set (`RendezvousParkAltM`, reads `v.targetObject`; guarded by same-body + `ParkInsertFloorKm` 185 km; falls back to the 200 km default with no target).
