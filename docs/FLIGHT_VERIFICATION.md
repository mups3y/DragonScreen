## SAS / MechJeb attitude-hold investigation (2026-08-31, owner-asked; research, no code change)
How KSP SAS + MechJeb hold attitude, and whether they solve the RCS pulsing (verified vs source + `MECHJEB_MASTER_MAP.md` §"actual lever"):
- **KSP stock SAS:** a continuous PID (`SASController`) drives pitch/yaw/roll to a target orientation. Smooth + fuel-free on **reaction wheels** — but the Dragon has **NONE**; on RCS a continuous PID → **bang-bang chatter** (our exact problem). SAS is not the fuel-efficient model for an RCS-only vehicle.
- **MechJeb SmartASS + AttitudeController (BetterController):** SmartASS only picks the attitude *reference* (KILLROT/prograde/target/…); the controller is a continuous cascade PID → KSP bang-bang. **MechJeb applies NO PWPF and NO phase-plane deadband to RCS** (its delta-sigma modulator is wired only to the hoverslam ENGINE). **Translatron/`MechJebModuleRCSController`** = a translation velocity PID → s.X/Y/Z, with `RCSBalancer` distributing **translation** across thrusters — **rotation balancing explicitly unsupported.**
- **⇒ Neither SAS nor MechJeb solves it** — both feed a continuous torque demand to on/off thrusters → the limit-cycle chatter that drains MMH. Copying them would not help.

## ⭐ RCS OVER-THRUST ROOT CAUSE (owner-reported 2026-09-01: "thrusters stop pulsing so much when I drop the thrust limit under 90%") — CONFIRMED config mistake
The attitude chatter/limit-cycle (and a big share of the 97%-attitude fuel drain) has a **root cause the phase-plane deadband was only masking**: the pod Dracos fire at **5× the thrust the fine-control design intended.**
- **Confirmed on the flown vehicle:** `docs/flights/DS-ASC-008_geometry_dump_pad.csv` shows the pod (`TE.18.DRAGONV2.POD`, 16 Dracos in 2 blocks) at **`power_kn = 2`** = RO's realistic **0.4 kN × the plugin's ×5 boost** (`plugin/GameData/DragonScreen/DragonScreen.cfg:141-147`, `@thrusterPower *= 5`).
- **The mistake:** the ×5 exists to give the under-nozzled model realistic *translation* accel (~0.15 m/s²), and the cfg comment (`DragonScreen.cfg:134-139`) is explicit it must be paired with **dialing `thrustPercentage` DOWN per task (`CapsuleRcs`: ~20% dock / ~40% attitude, 100% only for burns).** **That `CapsuleRcs` scale-down was removed in the rebuild — only the comment survives** (`grep` finds `CapsuleRcs` nowhere in `plugin/src`). So fine attitude hold runs at the full 5×.
- **Why it chatters (quantified from the flown MOI + delivered torque):** the minimum 0.06 s pulse (`FlightDriver.RcsPulseMinOn`) at 2 kN kicks the rate **~0.05–0.50 °/s** (roll worst) — **≥ the 0.2 °/s rate deadband** — so the loop overshoots the band every pulse → bang-bang limit cycle. Lowering the limiter shrinks the min-impulse below the band → it settles.
- **Why "90%" specifically:** `RcsPulseFull = 0.90` (`FlightDriver.cs:174`) — at commanded actuation ≥0.90 the thruster fires CONTINUOUSLY (no pulse). Dropping the limiter forces the loop to command more actuation → it crosses 0.90 → continuous (non-pulsing). The owner's manual limiter reduction re-implements the removed per-phase scale-down.
- **Honesty (E1/S8):** the phase-plane deadband (`a6eb15f`) treated the SYMPTOM. The root cause is the ×5 over-thrust in fine control.
- **➡ ITERATION 1 APPLIED (owner-directed 2026-09-01: "go back to stock settings" + "why doesn't the autopilot just turn on SAS"):** REVERTED the ×5 → **stock 0.4 kN** Dracos (`DragonScreen.cfg`, `@thrusterPower *= 1`). L1 green (731,239 checks); installed (full restart owed). Rationale: at stock thrust the min-impulse bit is 5× smaller (≪ the deadband) so fine attitude is naturally calm, and a simple hold (even stock SAS, which uses RCS with no reaction wheels) becomes viable. **⚠ V4 invalidations from this change:** the max-Q ABORT RCS authority (flight-proven) and the de-orbit both use the pod Dracos → re-fly owed; translation + de-orbit burns are now ~5× slower. **Plan (owner's "rule loop"):** (1) test-fly stock thrust, record RCS use; (2) test SAS-hold (`Steering.UseGimbalLoop=false` path already exists, `Steering.cs:113-123`) with RCS+SAS both on, measure how much RCS SAS uses to hold — vs iteration 1 (one change → one verification, V3); (3) then re-tune to proper real-world figures (boost only during dedicated burns), not a blunt always-on ×5.
